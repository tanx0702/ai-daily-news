# 跨语言绑定门禁调整方案（待确认）

## 一、现状

### 1.1 两道关卡

跨语言（英文原文 + 中文展示）绑定由 `src/briefing/validator.py` 判定，分两步：

| 关卡 | 位置 | 规则 | 现状 |
| --- | --- | --- | --- |
| ① 拉丁锚点 | `claim_anchors <= quote_anchors`（约 606 行 / 104 行） | claim 中所有拉丁词必须出现在原文 quote 中 | **正确有效**，实测 4/4 通过 |
| ② 中文残留 | `_cross_language_rule_only_verifiable_with_markers`（约 226 行） | 删掉受控中文词后，claim 不得残留任何中文 | **瓶颈**，实测 4/4 失败 |

### 1.2 实测证据（干跑 #6，真实要闻）

LLM 生成的标题语义完全正确、拉丁锚点全部合规，但被第②关拒绝：

| LLM 标题 | ① 拉丁锚点 | ② 删受控词后残留 | 判定 |
| --- | --- | --- | --- |
| `Google DeepMind成立研究院以拓宽AGI辩论` | ✅ 通过 | `成立研究院以拓宽辩论` | ❌ 拒绝 |
| `Claude Code重新推出Projects功能，用于在云端管理多个AI代理` | ✅ 通过 | `重功能用云端管理多个代理` | ❌ 拒绝 |
| `OpenAI发现其模型给后续模型留纸条以隐藏不良行为` | ✅ 通过 | `发现给续留纸条以隐藏不良行` | ❌ 拒绝 |
| `Base Labs启动与Hugging Face和Goodfire的开放权重AI安全合作伙伴关系` | ✅ 通过 | `启动开放权重安全合作伙伴关系` | ❌ 拒绝 |

残留词全部是**正常新闻中文名词**（研究院、辩论、功能、云端、合作伙伴关系），不是幻觉。

### 1.3 根本原因

第②关的设计假设是「展示与原文同语言」：原文是英文时，任何中文都不在原文中，因此只允许极少量动作/虚词。它**无法区分**：
- 「研究院」= `institute`（正确翻译）
- 「收购英伟达」（原文未提及的编造）

对系统而言两者都是"原文里没有的中文"。结果是**正常的翻译整体被判不可信**，只有几乎不翻译的标题（GitHub 仓库名 + "发布"）能通过。

## 二、提议的新规则

### 2.1 原则

- **保留第①关**：拉丁锚点必须来自原文，防编造专名/数字 → 不变。
- **重写第②关**：从「删受控词看残留」改为「中文分词后逐词三类判定」。

### 2.2 逐词判定

对 claim 的中文部分**按词**（而非整串）判定，每个中文词必须落入以下之一：

| 类别 | 判定 | 依据 |
| --- | --- | --- |
| A. 受控动作/虚词 | 已在 `_CROSS_LANGUAGE_RULE_ONLY_MARKERS` | 现有词表 |
| B. 可翻译新闻名词 | 命中**受控中英对应词表**，且**其英文对应词出现在原文 quote 中** | 新增 |
| C. 其它 | 拒绝 | 保守 |

关键约束：**类别 B 必须要求英文对应词出现在原文中**——这是防幻觉的核心，杜绝「原文没说但中文写了」。

### 2.3 需要解决的技术问题

现有实现是「先删受控词、再看整串残留」，会把词切碎（实测残留 `重功能用`、`给续隐藏不良行`），导致词典无法匹配英文标签。因此必须改为**先分词、再逐词判定**，不能沿用字符串替换。

分词方式建议：最长优先匹配（先匹配词表中较长的中文词），对未匹配的连续中文串按常见二字/三字切分，仍无法归类的整段拒绝。

## 三、初始词表范围（需你确认）

建议只收**高频、语义明确、不易产生歧义**的新闻名词，先覆盖实跑出现的词，例如：

| 中文 | 英文对应（必须出现在原文） |
| --- | --- |
| 研究院 | institute / lab / laboratory |
| 辩论 | debate |
| 合作伙伴关系 / 合作 | partnership / partner / collaboration |
| 代理 / 智能体 | agent / agents |
| 功能 | feature / function |
| 云端 | cloud |
| 管理 | manage / management |
| 模型 | model / models |
| 行为 / 不良行为 | behavior / misbehavior |
| 安全 | safety / security |
| 开放权重 | open-weight |
| 成立 | launches / establishes / founds |
| 重新推出 | relaunches |
| 削弱 / 拓宽 | widen / broaden |
| 成本 / 价格 | cost / price |
| 训练 | training / train |

**明确不收**：机构名、人名、模型名、数字、版本号（这些必须走第①关的拉丁锚点）。

## 四、风险与边界

- 放行范围**严格受限于**「英文对应词出现在原文」+「拉丁锚点合规」，编造内容仍被拒。
- 词表扩大本身即为风险面，因此**只收必要词**，并保留测试锁定「编造内容必须拒绝」。
- 第①关不放宽，故 LLM 编造新实体/数字仍无法通过。
