# X 署名观点与来源扩容设计

## 背景与目标

项目面向微信公众号读者整理“AI 圈新闻与热点”，不应只收录机构公告。X 上研究者、技术领袖和产业观察者的原创判断具有独立阅读价值，但观点不能被改写为已经发生的客观事实。

本设计在现有事实简报流水线中增加 `attributed_opinion` 内容类型，并扩大 X 的最终容量。事实门禁、原始证据绑定、事件去重、微信链接和失败降级仍然有效。

## 发布构成

- 每期仍发布 5-15 条内容。
- `fact_event` 为事实新闻，整期至少 3 条。
- `attributed_opinion` 为署名观点，整期最多 3 条，可以计入最低 5 条。
- X 候选软目标为 5 条，硬上限为 8 条；软目标不能绕过质检或硬凑。
- 同一 X 作者每期最多 1 条，同一议题最多 1 条观点。
- 有官网、论文或专业媒体原文时，事实事件优先使用非 X 规范来源；人物观点仍链接本人原帖。
- 观点不足时使用更多合格事实新闻回填；事实新闻不足 3 条时仍然 `block`。

## 内容契约

### 事实新闻

`content_type=fact_event` 沿用现有规则：标题必须包含可核验主体、事件动作和具体细节，所有显示声明绑定规范来源证据。

### 署名观点

`content_type=attributed_opinion` 只接受 `config/x_sources.json` 中显式设置 `opinion_eligible=true` 的自然人账号。机构账号、媒体账号、未登记人物和资讯搬运号不能自动生成署名观点。

一条观点必须同时满足：

1. 来自白名单人物本人原帖，不是纯转发或只含链接的帖子。
2. 正文包含可识别的主张、判断、预测、质疑、比较或技术评价。
3. 回复帖只有在线程上下文完整且观点本身可独立理解时才可进入；缺少父帖时拒绝。
4. 引用帖必须保留作者自己的实质评论；只引用他人内容时拒绝。
5. 排除招聘、活动宣传、课程推广、祝贺、寒暄、表情、无实质短句和无法定位原话的二手转述。
6. 观点摘要只能压缩原意，不能补充事实、动机、影响或立场强度。

标题固定使用归因结构，例如“Yann LeCun 认为……”或“Karpathy 对……提出质疑”。不得把“某人预测 X”改写为“X 将发生”，也不得使用“证实”“宣布”等超出原帖的事实动作。

`brief` 最多一至两句：第一句补充观点原文中的限定条件，第二句可说明原帖上下文；没有增量信息时使用 `title_only`。每个标题和摘要句都必须绑定同一条本人原帖中的逐字证据。

人物涉及本人任职机构、投资项目或产品时，审计记录 `affiliation_disclosure=true`；展示文案使用“其所在机构”或明确机构关系，不把该观点描述为独立第三方评价。

## 数据流与选择

```text
X 快照
  -> 账号配置与帖子关系解析
  -> fact_event 确定性发布性预检
  -> attributed_opinion 原创性/观点性预检
  -> 事实事件聚类与观点议题聚类
  -> 内容 LLM 仅翻译/压缩
  -> 分类型确定性校验与证据绑定
  -> 先保证 3 条事实，再按排名填充，总观点 <= 3、X <= 8、同作者 <= 1
  -> DraftDecision(create|block)
```

事实事件与观点使用不同校验器，但共用来源证据、语义去重预算、审计、媒体、渲染和微信发布链路。观点不能被事实事件回填逻辑转换为事实；分类不确定时拒绝或按更严格的事实规则处理。

## 去重与排序

- 同一人物连续帖表达同一主张时，只保留证据最完整的一条。
- 多人对同一议题发表相似观点时，默认只保留一条；优先原始提出者、技术细节更多者和证据更完整者。
- 观点与事实新闻涉及同一事件时可以共存，但事实新闻优先排序，观点必须提供新增判断而非复述新闻。
- 排序信号包含来源资格、原创性、文本完整度、技术细节、新鲜度和互动热度；互动量只能排序，不能证明观点真实性或重要性。

## 展示与审计

网页和微信正文为观点条目显示“圈内观点”标签，保留作者名称、原帖时间和 X 原帖链接。标签不使用“权威结论”“证实”等背书性表达。

`docs/debug/<date>-briefing.json` 为每个观点候选记录：

- `content_type`
- `opinion_author`
- `opinion_eligible`
- `original_post`
- `context_complete`
- `stance_type`
- `affiliation_disclosure`
- 构建、验证、去重和最终原因码

新增原因码至少区分 `opinion_author_not_allowed`、`opinion_repost_only`、`opinion_context_missing`、`opinion_no_substantive_claim`、`opinion_promotional_content`、`opinion_attribution_missing` 和 `opinion_claim_not_source_bound`。

## 失败与降级

- 观点分类 LLM 缺失、超时或响应无效时，只接受确定性规则能够识别明确归因、观点动作和逐字锚点的条目；其余拒绝，不转人工复核。
- X 快照过期、账号采集失败或上下文缺失时，跳过对应观点，不影响事实新闻和其它来源。
- 合格观点少于目标时不 block，由事实新闻回填；事实新闻少于 3 条或总条目少于 5 条时 block。
- X 最终超过 8、观点超过 3、同作者超过 1 或观点缺少本人原帖证据时，`DraftDecision` 必须 block。

## 测试与上线

测试覆盖配置 schema、原创帖/回复/引用/转发判断、归因标题、利益相关标记、观点证据绑定、同作者与同议题上限、3 条事实下限、观点最多 3、X 软目标 5 和硬上限 8，以及所有失败降级原因。

上线先以冻结 X 快照执行完整本地测试，再在服务器使用 `SKIP_WECHAT_DRAFT=1` 干跑。干跑必须形成至少 2 条事实，观点不超过 3，X 不超过 8，公开 HTML 与微信预览清楚区分“事实简报”和“圈内观点”；确认后才恢复真实草稿任务。
